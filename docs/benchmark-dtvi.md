# Initial TUM VI comparison with Kalibr

Recorded on September 17, 2026 using `dataset-calib-imu1_512_16.bag`, the TUM VI
recording referenced by DT-VI-Calib. Runs used the same host sequentially, with
no concurrent calibration container. Both camera–IMU runs read `cam0`, 1,038
images, and 10,345 IMU measurements, using the same fixed pinhole-equidistant
intrinsics generated by Kalibr and the same AprilGrid.

## Measurement method

[`scripts/measure_docker_run.sh`](../scripts/measure_docker_run.sh) polls Linux
cgroup v2 counters at nominal 100 ms intervals. The largest observed
`memory.peak` is a kernel-maintained high-water mark through the last sample.
The `anon`, `file`, and `kernel` values are sampled maxima, not exact peaks.
CPU time is the last sampled `cpu.stat/usage_usec`; wall time surrounds
`docker run`. The calibration commands included a one-second delay before
container exit to allow a final sample; this delay is included in wall time.
Final shutdown activity after the last sample may not be captured.

Category maxima need not occur simultaneously and must not be summed. Cgroup
anonymous memory is not identical to process RSS. File-cache charges depend
on Linux cache state and ownership, so total-memory comparisons require care.
ROS 1 input was used for Kalibr and converted ROS 2 MCAP for Kalibr2; conversion
time is excluded. These were single measurements, without controlled cold-cache
conditions, repeated trials, or explicit CPU pinning.

The separate Kalibr intrinsic run sampled 260 images at 5 Hz and optimized 20
views. Its cost is not included in the camera–IMU time ratio.

## Performance

| Stage | Wall time | CPU time | Peak cgroup | Sampled peak anonymous | Sampled peak file cache | Sampled peak kernel |
|---|---:|---:|---:|---:|---:|---:|
| Kalibr, cam0 intrinsics | 28.389 s | 37.604 s | 1,213.238 MiB | 414.121 MiB | 784.500 MiB | 14.594 MiB |
| Kalibr, cam0–IMU | 110.060 s | 142.252 s | 1,382.863 MiB | 612.449 MiB | 757.922 MiB | 16.324 MiB |
| Kalibr2, cam0–IMU | 17.316 s | 35.477 s | 1,020.094 MiB | 87.223 MiB | 929.141 MiB | 3.332 MiB |

Observed camera–IMU ratios are 6.36× for wall time, 4.01× for CPU time, and
7.02× for sampled anonymous memory. Total cgroup peak was 26.2% lower for
Kalibr2. These describe the measured pipelines, not a speedup at matched
accuracy or identical solver workload.

Kalibr2 detected the target in **146 of 1,038 images** and optimized 145 camera
frames and 10,318 IMU samples. Kalibr's log reported corner extraction for all
1,038 images. Detection acceptance, retained corner sets, spline models, and
bias models differ. Investigating these differences and evaluating shared
observations are prerequisites for attributing gains to parallelism alone.

## Numerical results

| Metric | Kalibr | Kalibr2 |
|---|---:|---:|
| Reprojection | mean 0.08373 px | RMSE 0.45732 px |
| Offset: `t_imu = t_cam + shift` | +0.16258 ms | -0.19245 ms |
| Input IMU samples | 10,345 | 10,345 |
| Input cam0 images | 1,038 | 1,038 |

Extrinsics differ by approximately 1.166 mm in translation and 0.0380 degrees
in rotation. The time offsets differ by 0.35503 ms. Reprojection errors cannot
rank accuracy directly: retained observations and aggregation differ. Absolute
accuracy requires an appropriate reference and validation on independent data.

## Reproducibility status

Raw bags, observation caches, PDFs, and logs are not versioned. Generated
artifacts from these runs were removed during repository cleanup. The tables
preserve recorded measurements, but the original runs cannot be fully audited
from this repository alone. The measurement script supports new runs; preserve
commands, input hashes, image IDs, raw metrics, and calibration artifacts for
future comparisons, and repeat trials in alternating order.
